# Capybara baseline, 2026-10-18

These numbers come from synthetic data on the available 12-logical-CPU Linux host. They are reproducible with [`scripts/benchmark.go`](../../scripts/benchmark.go), [`scripts/benchmark_query.go`](../../scripts/benchmark_query.go), and [`scripts/benchmark_otlp.go`](../../scripts/benchmark_otlp.go). They do not represent an independent 4-vCPU/8-GB machine or a customer trace.

| Measurement | Result |
| --- | ---: |
| Paced SQLite ingest, 50 spans per batch, 10 minutes | 300,000 sent; 300,000 stored; 499.99 spans/s |
| Paced OTLP HTTP ingest, 50 spans per request, 10 minutes, GOMAXPROCS=4 | 300,000 sent; 300,000 stored; 500.00 spans/s; 0 retry responses |
| OTLP HTTP receiver RSS at end of ingest | 34.7 MB |
| OTLP HTTP database plus WAL/SHM at end | 91.8 MB |
| Additional unpaced seeding | 1,000,000 total spans across 20,000 runs |
| List 50 runs, 100 queries across offsets 0–19,950 | p95 2.62 ms |
| Open one 50-span run, same 100 positions | p95 0.45 ms |
| Process RSS after seeding and queries | 27.2 MB |
| SQLite database plus WAL/SHM during run | 252.7 MB |

The first ingest workload writes directly through `Store.WriteBatch`. The OTLP workload sends actual HTTP protobuf requests to the receiver, checks response codes, and verifies the final database count. Both exclude recorded bodies, logs, metrics, the analyzer, concurrent users, and the TUI. The generated traces have one run for every 50 spans; query measurements are warm-cache and serial. `GOMAXPROCS=4` limits Go execution but is not an independent 4-vCPU/8-GB host. No real-user task timing or detector precision outside the curated corpus has been measured here.
